# 출퇴근 지하철 위젯

iOS Scriptable 위젯. 발산 ↔ 완정 출퇴근길의 환승역 도착 정보를 한 화면에 모아 보여준다.

```
출근   발산(5호선) → 김포공항(공항철도) → 검암(인천2호선) → 완정
퇴근   완정(인천2호선) → 검암(공항철도) → 김포공항(5호선) → 발산
```

도착역은 조회할 필요가 없으니 실제로 표시하는 구간은 방향당 3개다.

## 데이터 출처

| 구간 | 출처 | 방식 |
|---|---|---|
| 발산·김포공항 (5호선) | 서울시 실시간 도착정보 API | 실시간 |
| 김포공항·검암 (공항철도) | AREX 실시간 열차정보 | 실시간 |
| 검암·완정 (인천2호선) | 인천교통공사 공개 시간표 | 시간표 |

인천2호선은 공개된 실시간 API가 없어 시간표를 내장했다. 해당 행에는 `시간표` 표시가 붙는다.

## 설치

1. App Store에서 **Scriptable** 설치
2. [data.seoul.go.kr](https://data.seoul.go.kr) 가입 → 인증키 발급 (무료)
3. `subway-widget.js` 내용을 Scriptable에 새 스크립트로 붙여넣기
4. 맨 위 `SEOUL_API_KEY` 에 발급받은 키 입력
5. 홈 화면에 Scriptable 위젯(중간 크기) 추가 → 이 스크립트 지정

## 위젯 크기와 출근/퇴근

**큰(Large) 위젯**으로 배치하면 출근·퇴근 여섯 구간이 한 화면에 다 들어간다. 교대근무라
모드를 오가는 게 번거로우니 이쪽이 기본이다.

중간(Medium) 크기는 여섯 구간이 들어가지 않아서, `AUTO_COMMUTE_UNTIL`(기본 13시)을
기준으로 지금 쓸 쪽만 보여준다.

위젯 파라미터에 `출근` 또는 `퇴근` 을 넣으면 크기와 무관하게 그쪽만 고정된다.

지금 시간대에 해당하는 구획에는 노란 점이 붙는다. 순서는 항상 출근이 위다.

## 설정값

| 이름 | 설명 |
|---|---|
| `SEOUL_API_KEY` | 서울시 열린데이터광장 인증키 |
| `AUTO_COMMUTE_UNTIL` | 출근으로 볼 시각 경계. 강조 표시와 중간 크기 위젯에 쓰인다 |
| `TRAINS_PER_LEG` | 구간마다 보여줄 열차 수 (기본 2) |
| `COUNTDOWN_STYLE` | `relative` / `timer` / `static`. 위의 설명 참고 |
| `DIAG` | `true` 로 두고 앱에서 직접 실행하면 원본 응답을 클립보드에 복사 |
| `HOLIDAYS` | 인천2호선 공휴일 시간표 판정 목록. 매년 갱신 필요 |
| `ROUTES` | 구간 정의. 역 추가·변경은 여기만 고치면 된다 |

## 알아둘 점

- **남은 시간은 iOS가 직접 갱신한다.** 위젯 스크립트는 계속 돌 수 없으므로, 다음 열차의
  시각을 넘겨주고 표시를 iOS에 맡긴다. 스크립트가 다시 돌지 않아도 값이 움직인다.
- **`applyTimerStyle()` 은 멈추지 않는다.** 목표 시각이 지나면 그대로 위로 세기 시작하고,
  올라가는 중인지 내려가는 중인지 읽는 쪽에서 구분할 수 없다. 그래서 기본값은
  `applyRelativeStyle()` 이다. 지나간 열차를 `5분 전` 으로 적어 방향이 드러난다.
  대신 분 단위라 초는 보이지 않는데, 마지막 예측을 붙들고 초를 세는 건 어차피 없는
  정밀도였다. 정확한 시각은 보조 줄의 절대 시각을 본다. 이쪽은 위젯이 아무리 오래
  멈춰 있어도 틀리지 않는다.
- **위젯을 탭하면 즉시 다시 불러온다.** 버튼은 못 넣지만 위젯 전체가 새로고침 버튼이다.
- **실행 시간 예산이 있다.** 위젯 스크립트에 주어지는 시간이 넉넉하지 않아, 전 구간을
  한 번에 병렬로 부르고 전체 12초를 넘기지 않는다. 늦는 구간은 직전에 받아둔 값을
  흐른 시간만큼 당겨서 채우고 `N분 전 정보` 를 함께 적는다. 10분이 지난 값은 쓰지 않는다.
- **위젯 갱신 주기는 iOS가 정한다.** 코드에서 1분 갱신을 요청해도 실제로는 보통 5~15분
  간격이라, 위젯 표면의 숫자는 그만큼 지난 값일 수 있다. 위젯을 탭하면 즉시 갱신된다.
  서울시 API 응답은 `recptnDt` 기준 예측이라, 그동안 흐른 시간만큼 빼서 보정하고 있다.
- **공항철도 직통열차는 제외한다.** 김포공항·검암에 정차하지 않아서 `formType === "A"` 인
  열차는 걸러낸다.
- **인천2호선 시간표는 개정될 수 있다.** 인천교통공사 공지를 확인해서 갱신한다.

## 5호선이 계속 비면

`diagnose.js` 를 Scriptable에 따로 넣고 인증키를 채워 실행한다. http/https 각각에
대해 응답 시간과 오류 코드를 찍고 결과를 클립보드에 복사한다.

| 증상 | 원인 |
|---|---|
| 둘 다 실패 + 시간 초과 | 서울시 서버가 느리거나 망에서 막힘 |
| `ERROR-300` / `ERROR-500` | 인증키 문제. 발급 직후면 활성화까지 기다린다 |
| `INFO-200` | 역명이 맞지 않음. "역" 을 빼고 적는다 |
| http만 성공 | 정상. 위젯도 http를 먼저 쓴다 |

## 구간 추가하기

`ROUTES` 배열에 항목을 넣는다. 개수 제한은 없다.

```js
// 서울시 API (서울시 구간만 조회된다)
{ line: "line5", station: "우장산", via: "발산 방면",
  source: "seoul", subwayId: "1005", dests: ["방화"] }

// AREX (code 는 스크립트 주석의 역코드 표 참고)
{ line: "arex", station: "계양", via: "서울역 방면",
  source: "arex", code: "060", dir: "up" }
```
